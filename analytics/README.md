# Analytics Pipeline

Profiles, cleans, and tells a visual story about the Titanic dataset (Part A), then builds
and rigorously evaluates a full predictive-modeling pipeline on top of it (Part B).

## Setup

```
pip install -r requirements.txt
```

## Run end to end

```
python 01_eda.py         # -> titanic.csv (raw fallback), EDA_REPORT.md, charts/
python 02_modeling.py    # -> MODELING_REPORT.md, charts/, model_pipeline.joblib
```

`01_eda.py` loads `sns.load_dataset('titanic')` — the **one and only** network/cache load of
the raw dataset — and immediately saves it to `titanic.csv`. `02_modeling.py` reads that same
`titanic.csv`, so the raw dataset is never loaded from the network a second time.

**Note:** every written interpretation in `EDA_REPORT.md` and `MODELING_REPORT.md` (skewness
conclusion, correlation interpretation, chart interpretations, imbalance-strategy conclusion,
heteroscedasticity conclusion, final recommendation) is generated **programmatically from the
actual computed statistics** at run time — the text is built from real f-string-interpolated
numbers, not pre-written, so the reports reflect whatever this run's real data produces.

## Design decisions

- **Missing values:** threshold rule applied per column — `embarked`/`embark_town`
  (<5% missing) have those rows dropped; `age` (~20% missing) is median-imputed;
  `deck` (~77% missing) is dropped entirely as unreliable to impute at that rate
  (see the exact percentages and reasoning generated in `EDA_REPORT.md`).
- **Correlation matrix:** restricted to exactly `survived, pclass, age, sibsp, parch, fare` —
  `adult_male` and `alone` are excluded as derived/redundant flags, per the spec.
- **Modeling features:** `pclass, sex, age, sibsp, parch, fare, embarked`. Excluded:
  `alive` (directly encodes the target — would leak), `deck` (dropped for missingness),
  and `who`/`adult_male`/`alone`/`class`/`embark_town` (redundant derivations of columns
  already included).
- **Leakage prevention:** the train/test split happens before any preprocessing; all
  imputation/encoding/scaling is done inside a `ColumnTransformer` wrapped in a
  `Pipeline`, fit only on the training split. The `GridSearchCV` hyperparameter search
  wraps the *same* preprocessing + estimator pipeline, so each inner CV fold refits
  preprocessing on that fold's own training portion only.
- **Imbalance comparison:** run on Random Forest specifically, comparing baseline,
  `class_weight='balanced'`, and SMOTE (SMOTE applied only to the already-preprocessed
  training fold, never to the test fold).
- **Regression side-task:** predicts `fare` from `pclass, sex, age, sibsp, parch, embarked,
  survived` using a separate train/test split and its own preprocessing pipeline.
- **Saved artifact:** `model_pipeline.joblib` is the complete tuned Random Forest pipeline
  (preprocessing + estimator together), reloadable and directly usable on raw, unprocessed
  input rows — verified by a reload-and-predict check at the end of `02_modeling.py`.

See `EDA_REPORT.md` and `MODELING_REPORT.md` (generated by running the scripts above) for
the full write-up: missing-value percentages, IQR outlier counts, skewness conclusion,
survival-rate breakdowns, correlation interpretation, all 4 chart interpretations, the
imbalance-strategy conclusion, GridSearchCV best params + OOB score, regression metrics
and heteroscedasticity conclusion, and the final model comparison table with recommendation.
